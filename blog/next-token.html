Predict the next token.

An LLM is a next-token predictor. Tokens in, probabilities out, one token at a time. This note builds the smallest honest version of that machine — a model small enough to read — and runs it.

DRAFT 2026~4 MIN3 FIGURESMODE: LLM-BASICSMD VERSION →

01What an LLM does

Every answer an LLM gives you is written one token at a time, and no token is chosen in the sense you might think. The model looks at what it has written so far, computes a probability for every token it knows, and picks one. Then it repeats with the longer text. That loop is the whole machine — the rest is scale.

An LLM is a next-token predictor. Chat, code, reasoning — all of it is that single step, repeated.

02Tokens, not letters

A model does not read letters, and it does not really read words. It reads tokens — chunks a tokenizer learned to split text into. The classic learning rule is byte-pair encoding: count how often every adjacent pair appears, merge the most common pair, repeat until nothing repeats. This figure runs that rule on a toy corpus:

Every count is real: "e"+"s" appears nine times in this corpus, so it merges first. The merges are greedy — whichever pair is most frequent wins, ties going to the pair seen first — and each merge leaves the corpus one token shorter until every word is a single token.

The counts, the merge order and the vocabulary on this figure are all computed by the byte-pair algorithm running on this page. The corpus is toy; the algorithm is the one real tokenizers use.

03The table

Once the text is tokens, the model needs something to predict with. It learns a table: given the tokens seen so far, what comes next, and how often. This toy uses a trigram table — the next token depends on the last two. Step through the corpus and watch the table get built:

A production LLM is the same shape with billions of rows, learned by attention layers over billions of tokens. The toy's table fits on screen.

04The loop

Running the model is a loop of three lines: take the last two tokens, read the row, pick the most likely next token, append it. That is everything. Press play:

// the whole model: one lookup, one argmax
// counts[ctx] = tokens that followed ctx during training
function next(ctx) {
    var row = counts[ctx];          // e.g. { met: 1, slept: 1 }
    var best = null, n = 0;
    for (var tok in row)            // pick the most frequent
        if (row[tok] > n) { n = row[tok]; best = tok; }
    return best;                    // one token — call it again
}

The generated text reads almost like English — the fox met a crow the crow sang a song the song went on and on. Then the context the fox comes back and the toy re-enters its sixteen-token loop. It cannot stop, because the corpus never showed it an end. Fluency without understanding is exactly what this loop buys, at every scale.

Ties in the table break toward the token that appears first in the corpus — deterministic, so the same figure replays identically. The model, its table and the generated text are all computed by the code on this page.

05The ceiling

The loop also explains the failure modes. The toy loops because the corpus ended; a real model confabulates because it only ever samples the table. A confident falsehood is not a malfunction of next-token prediction — it is next-token prediction: the token that best fits the table, written whether or not it is true.

Next-token prediction is not understanding. It is the best-fitting continuation, sampled one token at a time.
