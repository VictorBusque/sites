Token by token.

An LLM is a next-token predictor. This page trains a real toy model on twelve sentences, then walks the loop that writes every answer — read, score, pick, append — while the whole vocabulary competes for every token.

01Tokens, not words

A language model does not think in words. It thinks in tokens — chunks of text that a tokenizer cuts a sentence into before the model ever sees it. For the toy model on this page, tokens are simple: words, plus the period, each one its own cell. Case is not folded — The and the are different tokens.

The model on this page trains on the twelve sentences you will meet in a moment. It is a real model — a trigram — and every number you will see is computed from those sentences by the code that draws it. Nothing here is typed in.

02The distribution

At every step the model's whole job is one number per token: the probability that it comes next. From the pair The cat, the corpus splits the bet five ways — sat, saw, ran, slept, ate each get 6.5%, and the other 21 tokens share the long tail at 3.2% each. With 79 tokens of training data, the distribution is nearly flat: everything is a long shot.

Greedy takes the largest probability, and ties break by vocabulary order — so the first run of the loop reads sat, on, the, mat, period: a sentence the corpus approves of. Sampling rolls the dice against the same scores instead, and with a distribution this flat, the dice find wilder places.

03Why the loop matters

Everything a language model does — chat, code, translation, calling a tool — is this loop, repeated. The difference between the toy and a production model is not the loop. It is the size of the bet: millions of tokens of vocabulary, billions of parameters shaping the scores, and a context measured in hundreds of thousands of tokens instead of two.

That two-token memory is why the toy drifts: after the period it has no idea what came before, so every continuation looks plausible. Real models carry more context and sharper distributions, and the drift shrinks. But the structure is identical — read, score, pick, append — repeated until the model decides it is done.

An LLM is the loop. The model is what the loop runs.
