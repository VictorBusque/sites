01How this page works

Every article on this site is a scrollytelling story: one idea, told as a sequence of scenes, and the scroll is the timeline. A sticky-scene pins a dark diagram to the viewport while step cards scroll over it — each step is one named state of the diagram, and the reader controls the clock by scrolling.

Each section below is a working example of one piece. Copy the markup, keep the shared files, write the content.

02The recipe

A sticky scene is a tall track: a pinned stage plus one article.step per diagram state. The scene module in js/scene.js watches the steps and toggles is-active, so the page itself needs no scene JavaScript — only CSS keyed off data-active-step.

<!-- sticky scene: engine activates steps, sets data-active-step -->
<section class="sticky-scene">
    <div class="sticky-scene__stage" aria-hidden="true">
        <div class="scene-head">
            <span class="scene-no">ACT 02</span>
            <span class="scene-name">THE MECHANISM</span>
            <span class="scene-readout" data-readout></span>
        </div>
        <div class="stage"><!-- the diagram --></div>
    </div>
    <div class="sticky-scene__steps">
        <article class="step" data-step="1">
            <span class="step-k">STEP 01 / 03</span>
            <p>One short paragraph. Real text, real conclusion.</p>
        </article>
        <article class="step" data-step="2">…</article>
    </div>
</section>

/* stage states are named, not pixel-driven */
.sticky-scene[data-active-step="2"] .marker { transform: translateX(60px); }

Steps are real DOM text in reading order; the overlay layout exists only under the .js gate in <head>. Disable JavaScript and the same page becomes a plain document — stage first, steps stacked — still a complete article. That is the fallback, and it is never optional.

For continuous scroll-linked effects (a marker easing along a path, a bar filling), feature-detect and keep a base state:

@supports (animation-timeline: view()) {
    .stage .path-progress {
        animation: fill 1s linear both;
        animation-timeline: view();
        animation-range: entry 0% cover 40%;
    }
}
/* outside @supports the element simply rests at its base state */
The story is the article. Scenes sit at the center — the prose tells you what is happening and why it matters.

03A split scene — quiet, bounded

Not every idea needs a pinned stage. A split scene keeps a small visual beside the copy — ambient life, a settled diagram, a shape that explains itself. It reads like a figure in a magazine: no travel, no timeline, just the two parts agreeing.

On narrow screens the pair stacks: copy first, visual after.

The scroll is the timeline. The story is the article.

Primary motion.

The thing the reader follows — one clear action per scene.

Secondary motion.

Supporting cues — a glow, a shadow, a pulse that lands with the action.

Ambient life.

Background motion that keeps the scene alive without demanding attention.

Conventions: scenes carry ACT labels and STEP k / n cards; every number shown is the real state — computed by the code that renders it, never decoration. Reduced motion and no-JS collapse the overlay to a stacked document, and that stacked document is always complete.

05Putting it together

Copy this page as your starting point. Keep css/site.css, js/site.js and js/scene.js untouched; replace the hero, the acts, and the scenes. Every component on this page is a working example — delete what you do not need, keep what you do.

Every scene on this page also adapts to narrow screens: shrink the window to 390px and the race's cells shrink and its labels move above the rows. Full-bleed SVG scenes get the same treatment with a tighter data-vb-narrow frame — see the scrollytelling reference.
