01How this page works

Figures come in two kinds. Scripted figures are driven by a small draw(i, body) function — the engine builds the controls, calls your function once per step, and shows whatever string you return in the readout. Looping figures are pure CSS choreography with no JavaScript at all. Both get their controls automatically.

Each section below is a working example of one piece. Copy the markup, keep the shared files, write the content.

02A scripted figure — step through it

This is the heart of the site: a figure where every step is a real state, and the reader controls the clock. Eight cells, one marker. The engine adds PREV / PLAY / NEXT / RESET on its own, and the readout shows the live step.

To make one, register a script with three things: steps, draw, and optionally label. The body gets built once, then mutated per step:

<!-- scripted figure: engine adds PREV / PLAY / NEXT / RESET -->
<div class="fig-body" data-script="my_figure" data-autoplay data-loop data-speed="900">
    <div class="my-stage"></div>
</div>

<script>
    window.__figScripts = window.__figScripts || {};
    __figScripts.my_figure = {
        steps: 12,                                 // frames 0..11
        draw: function (i, body) {
            var stage = body.querySelector('.my-stage');
            // build DOM once, then change state per step
            return 'STEP ' + (i + 1) + ' / 12';    // shown in the readout
        }
    };
</script>

Add data-autoplay to start playing the moment the figure scrolls into view, and data-loop to wrap from the last step back to the first. data-speed sets the milliseconds per step.

03A looping figure — pure CSS

For ambient scenes with no state to read, skip the script entirely. The engine still adds PAUSE / REPLAY so readers can freeze the scene and look at it.

<!-- looping figure: pure CSS, engine adds PAUSE / REPLAY -->
<div class="fig-body">
    <div class="orb">
        <span class="ring"></span>
        <span class="core"></span>
        <span class="spin"><span class="sat"></span></span>
    </div>
</div>

/* css */
.orb .spin  { animation: spin 3.4s linear infinite; }
@keyframes spin { to { transform: rotate(360deg); } }

Here is the same engine doing real work: linear search against binary search on the same twelve numbers, looking for 55. It autoplays when visible and loops forever, and the readout reports the true probe counts — 8 probes against 4, both computed by the code on this page.

05Layout pieces

Every prose block you need, live. Section headings with numbers, a callout, an aside, tags, buttons, a masked quote, and a staggered card row that reveals on scroll.

The diagram is the article. The figures sit at the center of the story — the prose is there to tell you what to watch.

Ideas that move are ideas that stick.

Primary motion.

The thing the reader follows. One clear action per figure.

Secondary motion.

Supporting cues — a glow, a shadow, a pulse that lands with the action.

Ambient life.

Background motion that keeps the scene alive without demanding attention.

Conventions: figures are numbered FIG. 01 upward; captions always say what to watch; every counter shown is the real state, never decoration.

06Putting it together

Copy this page as your starting point. Keep css/site.css and js/site.js untouched; replace the hero, the prose, and the figures. Every component on this page is a working example — delete what you do not need, keep what you do.

Every figure on this page also adapts to narrow screens: shrink the window to 390px and the walker's cells shrink and the race lanes reflow. Full-bleed SVG figures get the same treatment with a tighter data-vb-narrow frame — see the figure engine reference.
